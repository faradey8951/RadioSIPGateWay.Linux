# Stage 8 Fix 1 — полярность PTT и безопасное завершение

## Настройка полярности

В секции `[Transmit]` используется параметр:

```ini
PttActiveLevel = Low
```

Допустимые значения: `High` и `Low`. Это электрический уровень GPIO3, который включает передачу; противоположный уровень отпускает PTT. Для проверенной платы с оптопарой активный уровень — **LOW**: GPIO3 стягивает ток светодиода оптопары к земле, оптопара открывает транзисторный выход и активирует PTT. GPIO3 HIGH — безопасный неактивный уровень.

Раннее предположение `PttActiveLevel = High` было неверным: ручная проверка с отключённым от радиостанции PTT-проводом подтверждала переключение GPIO, но не подтверждала полярность оптопары на входе радиостанции. Конфигурация AlterFRN `PTT=CM108:/dev/hidraw0:GPIO3:I` также означает инвертированную активную логику, то есть активный LOW.

`CosActiveHigh` — независимый параметр. Для `COS=CM108:/dev/hidraw0:VOLDN:N` установленный бит VOLDN (`raw & 0x02`) означает занятый канал, поэтому используйте `CosActiveHigh = true`.

## Почему PTT мог включаться сразу после ответа

При `VoxEnabled = false` каждый входящий RTP-кадр считается активностью, в том числе кадры цифровой тишины. Чтобы включать передачу только при речи, используйте:

```ini
VoxEnabled = true
```

и настройте `[VOX] ThresholdDbfs`, `ActivationDelayMs` и `ReleaseDelayMs`.

## Безопасное завершение

- `Ctrl+C` и `SIGTERM`: синхронно отправляется неактивный уровень GPIO3 до асинхронного останова сервисов.
- При остановке приложения контроллер повторно отправляет неактивный уровень несколько раз на открытом HID-дескрипторе и повторяет сброс непосредственно перед закрытием `/dev/hidrawN`.
- При ошибке HID дальнейшие запросы передачи блокируются; выполняются повторные попытки установить безопасный уровень.
- COS блокирует начало передачи. Если COS становится активным уже во время собственной передачи, текущий PTT сохраняется до окончания аудио (сам RF может влиять на COS); после отпускания PTT занятый канал блокирует повторное включение.

Проверяйте полярность на конкретной плате. Ни `Ctrl+C`, ни программная логика не гарантируют отпускание PTT при физическом отключении USB, зависании контроллера или потере питания. Для постоянной эксплуатации предусмотрите аппаратную подтяжку PTT к неактивному уровню.
