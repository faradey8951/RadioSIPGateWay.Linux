# Stage 6 — тест SIP/SDP/RTP без музыки

Этот этап сохраняет тест автоответа и согласования SIP/SDP/RTP, но явно устанавливает тестовый аудиоисточник SIPSorcery в `Silence`. После ответа звонящий не должен слышать музыку или тестовые тоны.

**Ограничения:** это всё ещё тестовая медиасессия. Она не подключает ALSA, не передаёт звук с CM108 в SIP и не воспроизводит принятый RTP в радиоканал. PTT/GPIO не используется. Не подключайте передатчик для этого теста.

## 1. Обновить и собрать

```bash
git pull
dotnet build src/RadioSipGateway.Linux/RadioSipGateway.Linux.csproj --configuration Release
```

## 2. Включить тест автоответа локально

В `config/radiogateway.local.ini`, секция `[SIP]`, оставьте:

```ini
AutoAnswerForRtpTest = true
```

Не публикуйте локальный конфиг с паролем.

## 3. Запустить

```bash
dotnet run --project src/RadioSipGateway.Linux --configuration Release --no-build -- --config config/radiogateway.local.ini
```

Позвоните на зарегистрированный SIP-аккаунт. Ожидаются `получен INVITE`, `180 Ringing`, успешное принятие вызова и сообщение `тестовый RTP-источник установлен в Silence`. После ответа звонящий должен слышать тишину, не музыку.

Завершите вызов со стороны телефона, проверьте запись о завершении вызова и остановите приложение Ctrl+C.

## 4. Что прислать

Пришлите полный журнал от старта до завершения тестового вызова. Если музыка всё ещё слышна, источник, вероятно, находится на стороне Yate или SIP-клиента; тогда понадобится сопоставить RTP-поток и серверную логику.

После теста установите `AutoAnswerForRtpTest = false`. Пока не используйте приложение как рабочий радиошлюз: ALSA, двусторонний аудиомост и PTT ещё не реализованы.
