# Stage 8 — CM108 GPIO3 PTT и VOLDN/COS

В этом этапе добавлено экспериментальное управление CM108 HID для проверенной платы USB `0d8c:000c`.

## Подтверждённые аппаратные значения

На тестовой плате:

- `/dev/hidraw0`, HID-интерфейс USB 03;
- входной отчёт `02 04 00 00` при активном VOLDN и `00 04 00 00` при неактивном VOLDN;
- VOLDN/COS читается по биту `0x02` первого байта входного HID-отчёта;
- GPIO3 управляется битом `0x04` `HID_OR1`; бит `0x04` `HID_OR2` переводит его в режим выхода;
- выходной HID-отчёт с report ID: `00 00 00 04 00` задаёт GPIO3 LOW, `00 00 04 04 00` — HIGH.

**Уточнение полярности после Stage 8:** ранняя версия документа ошибочно предполагала, что HIGH включает PTT. Отдельный ручной тест выхода с отсоединённым PTT-проводом подтверждал только переключение уровня GPIO, но не электрическую полярность всей оптопары/радиовхода. По фактической схеме платы (светодиод оптопары подключён к +5 В через резистор к GPIO3) GPIO3 LOW стягивает ток, включает оптопару и замыкает транзисторный выход PTT. Это также соответствует конфигурации AlterFRN `PTT=CM108:/dev/hidraw0:GPIO3:I`, где `I` — инвертированная активная логика (активный 0). **Текущая подтверждённая полярность: `PttActiveLevel = Low`; GPIO3 HIGH — безопасное неактивное состояние.**

Пример COS из AlterFRN `COS=CM108:/dev/hidraw0:VOLDN:N` соответствует нормальной активной логике: установленный VOLDN-бит означает активное состояние COS, то есть `CosActiveHigh = true`.

## Что делает программа

- `Transmit.PttEnabled=false` по умолчанию: PTT не открывается и не переключается.
- При `PttEnabled=true` программа открывает `HidrawPath`, конфигурирует GPIO3 как выход и сразу выставляет безопасный уровень, противоположный `PttActiveLevel`.
- Входящие SIP-аудиокадры вызывают запрос PTT; при `VOX` выключенном учитываются все входящие RTP аудиокадры. При `VOX` включённом используются RMS/dBFS и `VOX.ThresholdDbfs` с задержкой активации.
- Если VOLDN/COS сообщает занятость канала, новое включение PTT блокируется. Если COS срабатывает уже во время собственной передачи, PTT не сбрасывается: радиостанция может видеть собственный RF через цепь COS. После окончания аудио занятый канал блокирует следующую передачу.
- До первого входного HID-отчёта COS считается неизвестным, поэтому PTT не включается.
- При отсутствии входящих SIP-аудиокадров PTT отпускается после `PttReleaseDelayMs` (в Stage 9 значение по умолчанию — 700 мс).
- `Radio.SipToRadioTotSeconds` ограничивает непрерывную передачу; `Radio.SipToRadioTotLockoutSeconds` задаёт паузу после TOT.
- При завершении звонка и остановке приложения программа отправляет неактивный уровень GPIO3 несколькими HID-отчётами; это программная защита, не заменяющая аппаратную подтяжку PTT к безопасному уровню.

## Конфигурация для тестовой платы

В локальном `config/radiogateway.local.ini` (не добавлять его в Git, он содержит SIP пароль):

```ini
[Transmit]
Mode = cm108
HidrawPath = /dev/hidraw0
PttEnabled = true
PttActiveLevel = Low
PttPin = gpio3
CosSource = voldn
CosActiveHigh = true
PttReleaseDelayMs = 700
VoxEnabled = true

[VOX]
ThresholdDbfs = -45
ActivationDelayMs = 120
ReleaseDelayMs = 700
```

Сначала проверьте сборку и конфигурацию. Для первоначальной проверки GPIO оставляйте провод PTT физически отсоединённым от радиостанции. Проверьте COS отдельным радиосигналом и только после этого проводите короткий тест PTT с корректной антенной или эквивалентом нагрузки, разрешённой частотой и условиями передачи.

При `VoxEnabled=false` любой входящий RTP-кадр, включая цифровую тишину, считается активностью. Для передачи только при голосе используйте `VoxEnabled=true` и настройте порог и задержки.
