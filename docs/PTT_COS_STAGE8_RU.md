# Stage 8 — CM108 GPIO3 PTT и VOLDN/COS

В этом этапе добавлено экспериментальное управление CM108 HID для проверенной платы USB `0d8c:000c`.

## Подтверждённые аппаратные значения

На тестовой плате:

- `/dev/hidraw0`, HID-интерфейс USB 03;
- входной отчёт `02 04 00 00` при активном VOLDN и `00 04 00 00` при неактивном VOLDN;
- VOLDN/COS читается по биту `0x02` первого байта входного отчёта;
- GPIO3 управляется битом `0x04` `HID_OR1`; бит `0x04` `HID_OR2` переводит его в режим выхода;
- выход GPIO3 HIGH включает передачу, LOW выключает передачу.

Выходной HID-отчёт (пять байтов с report ID):

- LOW: `00 00 00 04 00`;
- HIGH: `00 00 04 04 00`.

Эти значения подтверждены отдельным безопасным тестом на конкретной плате. Другие ревизии CM108 могут требовать проверки.

## Что делает программа

- `Transmit.PttEnabled=false` по умолчанию: PTT не открывается и не переключается.
- При `PttEnabled=true` программа открывает `HidrawPath`, сразу конфигурирует GPIO3 как выход LOW и запускает чтение COS.
- Входящие SIP-аудиокадры вызывают запрос PTT; при `VOX` выключенном учитываются все входящие RTP аудиокадры. При `VOX` включённом используются RMS/dBFS и `VOX.ThresholdDbfs` с задержкой активации.
- Если VOLDN/COS сообщает занятость канала, PTT принудительно переводится в LOW и включение блокируется до освобождения канала.
- До первого входного HID-отчёта COS считается неизвестным, поэтому PTT не включается. После запуска нужно получить хотя бы один переход COS, чтобы программа знала состояние линии.
- При отсутствии входящих аудиокадров PTT отпускается после `PttReleaseDelayMs`.
- `Radio.SipToRadioTotSeconds` ограничивает непрерывную передачу; `Radio.SipToRadioTotLockoutSeconds` задаёт паузу после TOT. TOT блокирует повторное включение до окончания текущего вызова/активности.
- При завершении звонка и остановке приложения программа пытается установить GPIO3 LOW.

## Сначала проверить только конфиг и сборку

```bash
dotnet build src/RadioSipGateway.Linux/RadioSipGateway.Linux.csproj --configuration Release
```

## Конфигурация локального стенда

В `config/radiogateway.local.ini` (не добавлять этот файл в Git, он содержит SIP пароль):

```ini
[SIP]
AutoAnswerForRtpTest = true

[Audio]
CaptureDevice = plughw:1,0
PlaybackDevice = plughw:1,0
BridgeEnabled = true

[Transmit]
Mode = cm108
HidrawPath = /dev/hidraw0
PttEnabled = true
PttPin = gpio3
CosSource = voldn
CosActiveHigh = true
PttReleaseDelayMs = 250
VoxEnabled = false
```

Перед включением `PttEnabled=true`:

1. Для первого программного теста оставьте провод PTT физически отсоединённым от радиостанции. COS-провод при этом можно оставить на VOLDN.
2. Убедитесь, что GPIO3 LOW соответствует отпущенному PTT (на тестовой плате это уже проверено).
3. Проверьте именно внешний COS: при передаче с другой радиостанции приложение должно показать `COS: ... ЗАНЯТ`, а после окончания сигнала — `COS: ... СВОБОДЕН`. Не путайте нажатие локальной кнопки VOLDN с внешним COS, если они физически не соединены.
4. При запуске дождитесь логов `COS: ...`. До первого HID-отчёта PTT заблокирован.
5. Сделайте короткий SIP-вызов с отсоединённым PTT-проводом: проверьте логи GPIO3 HIGH/LOW. Только после этого подключайте PTT к радиостанции, убедившись в корректной нагрузке/антенне, разрешённой частоте и условиях передачи.
6. Первый реальный радиотест сделайте коротким. При `VoxEnabled=false` PTT может быть активен всё время поступления RTP-пакетов, даже если удалённый абонент молчит. Для дальнейшей эксплуатации предпочтительно настроить VOX и порог.

Во время первого теста наблюдайте:

- `COS: ... РАДИОКАНАЛ СВОБОДЕН/ЗАНЯТ`;
- `PTT: GPIO3 HIGH — ПЕРЕДАЧА ВКЛЮЧЕНА`;
- `PTT: GPIO3 LOW — передача выключена`.

**Ограничение:** это первый тест PTT/COS поверх тестового SIP auto-answer; не считать проект готовым к постоянной эксплуатации. При любой ошибке HID не продолжать передачу. `LOW` отправляется при завершении вызова и штатной остановке, но программная гарантия не заменяет аппаратную защиту PTT.
