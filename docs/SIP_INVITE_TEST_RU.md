# Проверка входящего SIP INVITE на Debian

Этот этап проверяет только доставку SIP INVITE до приложения. Так как RTP и ALSA ещё не подключены, программа намеренно отвечает `503 Service Unavailable`. Это ожидаемо и не означает, что разговор уже поддерживается. Перед тестом убедитесь, что приложение зарегистрировано на Yate.

## 1. Собрать

```bash
dotnet build src/RadioSipGateway.Linux/RadioSipGateway.Linux.csproj --configuration Release
```

## 2. Запустить с локальным конфигом

```bash
dotnet run --project src/RadioSipGateway.Linux --configuration Release --no-build -- --config config/radiogateway.local.ini
```

## 3. Позвонить на зарегистрированный SIP-аккаунт

С другого SIP-абонента позвоните на пользователя, заданного в `SIP.Username`. В журнале приложения должна появиться запись вида:

```text
SIP: входящий INVITE от 1001 на radio; отклонён ответом 503 Service Unavailable (RTP/аудио ещё не реализованы).
```

Номера в примере условные. Фактическое имя вызывающего зависит от заголовка `From` в SIP-запросе.

## 4. Что прислать для диагностики

Пришлите строки журнала вокруг входящего вызова и соответствующий фрагмент Yate-журнала. Удалите пароли, IP-адреса, если не хотите их публиковать, и другие секреты.

**Важно:** не подключайте PTT к передатчику на этом этапе. Ответ `503` ожидаем: медиатракт пока отсутствует.
